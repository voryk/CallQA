# CallGuard AI

Локальная система анализа записей звонков. API принимает WAV, MP3 и OGG до 100 МБ и 10 минут, сохраняет запись на локальном диске, ставит задачу в Redis/RQ. Worker использует faster-whisper и записывает текст и сегменты в PostgreSQL. Локальная Qwen через Ollama формирует предварительную оценку; в KPI и экспорт она попадает только после подтверждения сотрудником.

## Быстрый запуск

У этой сборки отдельное имя Compose `callguard-rachik5`, новые тома PostgreSQL/Redis/Ollama и отдельные порты. Распаковывайте в новую папку; старые данные не удаляются и не мигрируют автоматически. Повторный запуск с тем же именем использует те же тома и пароль. Перед первым запуском не переопределяйте `POSTGRES_PASSWORD` переменной PowerShell; используйте `Remove-Item Env:POSTGRES_PASSWORD -ErrorAction SilentlyContinue`. Для предыдущей базы не меняйте пароль в `.env` без изменения пароля PostgreSQL. Если порты заняты, измените `FRONTEND_PORT` и `API_PORT` до запуска. `docker compose down -v` удаляет тома — не применяйте без резервной копии.

Требуются Docker Desktop с Linux Engine и свободные порты 5174 и 8001 (можно изменить в `.env`).

1. Скопируйте `.env.example` в `.env` и задайте уникальный `POSTGRES_PASSWORD`.
2. Запустите `docker compose up -d --build`.
3. Установите модели Whisper и Qwen по инструкциям ниже до загрузки первого звонка.
4. Создайте первую учётную запись: `docker compose exec api python -m app.create_user admin --role admin`. Пароль вводится интерактивно, минимум 12 символов. Если пользователь `admin` уже существует, выполните `docker compose exec api python -m app.create_user admin --reset-password`.
5. Откройте http://127.0.0.1:5174. Состояние системы: http://127.0.0.1:8001/health/ready.

Для модели Whisper поместите готовую CTranslate2 модель в `models/whisper/` (включая `model.bin` и `config.json`). Для начальной проверки можно скачать модель в период подготовки:

```powershell
docker run --rm -v "${PWD}/models:/srv/models" callguard-rachik5-api:local python -m app.provision tiny
```

`tiny` подходит только для начальной проверки. Для качества, подходящего реальным звонкам, сравните `small` или `medium` на размеченной выборке и измерьте время обработки. После замены файлов модели перезапустите worker: `docker compose restart worker`.

Ollama запускается вместе с остальными сервисами, но её healthcheck больше не блокирует запуск worker. Полная оценка по четырём критериям требует установленной локальной Qwen. Один раз установите модель: `docker compose exec ollama ollama pull qwen2.5:3b`. Проверьте её командой `docker compose exec ollama ollama list`. Если оценка ранее завершилась ошибкой, нажмите «Повторить оценку» у расшифрованного звонка; повторная загрузка аудио не нужна. При работе приложение обращается к Ollama только по внутреннему адресу Docker. Записи и расшифровки не отправляются внешним сервисам.

## Структура

- `backend/app/main.py` — создание FastAPI и подключение маршрутов.
- `backend/app/api/` — маршруты авторизации, звонков, отчётов и проверки готовности.
- `backend/app/models.py`, `schemas.py`, `db.py` — таблицы, схемы API и подключение к PostgreSQL.
- `backend/app/security.py`, `audit.py`, `queue.py`, `config.py` — общие зависимости приложения.
- `backend/app/worker.py`, `assessment.py`, `retention.py` — фоновые задания, локальная оценка и удаление по сроку хранения.
- `backend/migrations/`, `backend/tests/` — миграции и тесты.
- `frontend/src/` — интерфейс React; `docker-compose.yml` — локальный запуск.

## Доступ и данные

- Роли: `viewer` просматривает звонки и дашборд; `analyst` загружает записи, повторно запускает неудачные задания, проверяет оценку и выгружает отчёты; `admin` дополнительно видит журнал действий.
- Пароли хранятся как Argon2-хеши. Сессии в Redis действуют 8 часов. Токен интерфейс хранит только в памяти вкладки.
- Создать пользователя: `docker compose exec api python -m app.create_user NAME --role analyst`.
- Сбросить пароль: `docker compose exec api python -m app.create_user NAME --reset-password`.
- Отключить пользователя: `docker compose exec api python -m app.create_user NAME --disable`.
- Файлы и записи звонков старше `RETENTION_DAYS` удаляются раз в сутки; по умолчанию 30 дней. События загрузки, просмотра звонка, экспорта, входа и проверки оценки пишутся в `audit_events`.
- PostgreSQL и Redis не публикуют порты на Windows. API и интерфейс доступны только с `127.0.0.1`.

## API и тесты

Документация API: http://127.0.0.1:8001/docs. Основные маршруты: `POST /api/login`, `POST /api/calls`, `GET /api/calls/{id}`, `POST /api/calls/{id}/retry`, `POST /api/calls/{id}/assess`, `POST /api/calls/{id}/review`, `GET /api/dashboard`, `GET /api/reports/csv`, `GET /api/reports/json`, `GET /api/reports/pdf`, `GET /api/audit` (только администратор). Дашборд, список звонков и все отчёты принимают `date_from` и `date_to` (включительно, UTC), по дате загрузки. В интерфейсе доступны день, неделя, 30 дней, 365 дней, весь период и произвольные даты. За один день отображаются 24 часа, длинные периоды группируются до 60 интервалов. Список звонков показывает последние 100 записей выбранного диапазона; отчёты и дашборд учитывают все записи. Защищённые маршруты требуют заголовок `Authorization: Bearer <token>`.

`docker compose run --rm --no-deps api pytest -q` запускает backend-тесты. `docker compose logs -f worker` показывает ошибки обработки. `docker compose stop` останавливает сервисы, сохраняя данные.

### Проверка сайта на звонке

После запуска и входа в интерфейс загрузите демонстрационную запись `samples/polite_bank_dialog.mp3`. Дождитесь статуса `completed`, раскройте «Контекст звонка» и оценку, затем подтвердите или отклоните её. Точный процитированный фрагмент проблемы будет подсвечен в расшифровке; отчёт PDF скачивается отдельно от KPI CSV/JSON.

Роли «Сотрудник банка» и «Клиент» определяются по характерным фразам, затем уточняются локальным сравнением спектральных характеристик, основной частоты и громкости (dBFS) с опорными репликами обеих ролей. Неоднозначные реплики остаются без роли. Это приблизительный метод, а не полноценная нейросетевая диаризация. Сегмент Whisper может содержать несколько говорящих; акустический профиль вычисляется для всего сегмента. Анализ тональности по словам доступен для сегментов без Qwen; среднее время ответа оценивается по паузам между соседними репликами клиента и сотрудника. Показатель отсутствует, если таких переходов нет. Если модель вернула цитату, которой нет в расшифровке, оценка помечается ошибочной, а не сохраняется с выдуманным доказательством.

Чтобы проверить 10-минутную запись, загрузите тестовый аудиофайл длительностью не более 10 минут. Значение «Транскрипция» и поле `processing_seconds` в KPI-экспорте измеряют время распознавания речи (без отдельной оценки Qwen). Время самой оценки сохраняется отдельно в `assessment.assessment_seconds`; эти замеры не включают ожидание в очереди. Это измерение зависит от модели Whisper и оборудования; результаты на тестовом MP3 нельзя считать нагрузочным тестом целевого сервера.

Для интерфейса: `cd frontend`, `npm ci`, `npm run build`.

## Условия банковского внедрения

Проверенное состояние проекта и решения, которые должен предоставить банк, собраны в [BANK_HANDOFF.md](BANK_HANDOFF.md).

Текущая сборка подходит для локального пилота, но не для обработки реальных клиентских записей без решения следующих задач совместно с ИБ и ИТ банка:

- Подключить согласованный банком провайдер входа сотрудников (OIDC/LDAP/AD), TLS на внутреннем адресе, управление секретами и шифрование диска/резервных копий. Сертификаты НУЦ сайта банка не определяют способ входа сотрудников в CallGuard.
- Согласовать схему ролей, журнал аудита с выгрузкой в SIEM, хранение и удаление резервных копий, восстановление после аварии и ограничения доступа администраторов.
- Проверить качество расшифровки и оценок на размеченной выборке банка; подтвердить точность распределения ролей и приближённого среднего времени ответа. KPI экспортируется после подтверждения оценки человеком.
- Измерить обработку 10-минутных звонков на целевом сервере, провести нагрузочные испытания, анализ зависимостей и проверку безопасности.
- Оценить точность распознавания, ролей и оценок на размеченных данных. Речевые маркеры и акустические признаки — вспомогательная эвристика; они не заменяют проверенную диаризацию.
- Согласовать способ шифрования PostgreSQL, файлов записей и резервных копий, а также централизованное хранение и ротацию ключей. Шифрование БД на уровне приложения не настроено.

Все зависимости, образы и модели для автономного контура нужно предварительно доставить во внутренний реестр. Установка моделей из интернета выполняется только при подготовке среды.

## Дополнения к текущей ветке

- Исходный дизайн, PDF-отчёт, цитаты нарушений и подтверждение аналитиком сохранены. Для старых звонков используйте «Пересчитать роли и оценку»; новая оценка снова требует подтверждения.
- Вывод `User already exists` означает, что администратор уже есть: используйте прежний пароль или `--reset-password`.
- Новые тесты: `cd backend` и `pytest -q tests/test_enhancements.py` (в контейнере: `docker compose exec api pytest -q tests/test_enhancements.py`).
- Не используйте `docker-compose.local.yml` для стандартной сборки: это необязательный override для локальной разработки с уже собранной папкой `frontend/dist`.
- Скачивание моделей требует сети при подготовке; сама обработка использует локальные модели. Полная сетевая изоляция не проверена.
