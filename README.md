# CallGuard AI

Локальная система анализа записей звонков. API принимает WAV, MP3 и OGG до 100 МБ и 10 минут, сохраняет запись на локальном диске, ставит задачу в Redis/RQ. Worker использует faster-whisper и записывает текст и сегменты в PostgreSQL. Правила формируют предварительную оценку; локальная Qwen может дополнять её; в KPI и экспорт она попадает только после подтверждения сотрудником.

## Быстрый запуск

Требуются Docker Desktop с Linux Engine и свободный порт 5173.

1. Скопируйте `.env.example` в `.env` и задайте уникальный `POSTGRES_PASSWORD`.
2. Запустите `docker compose up -d --build`.
3. Установите модели Whisper и Qwen по инструкциям ниже до загрузки первого звонка.
4. Создайте первую учётную запись: `docker compose exec api python -m app.create_user admin --role admin`. Пароль вводится интерактивно, минимум 12 символов. Если пользователь `admin` уже существует, выполните `docker compose exec api python -m app.create_user admin --reset-password`.
5. Откройте http://127.0.0.1:5173. Состояние системы: http://127.0.0.1:5173/health/ready.

Для модели Whisper поместите готовую CTranslate2 модель в `models/whisper/` (включая `model.bin` и `config.json`). Для начальной проверки можно скачать модель в период подготовки:

```powershell
docker run --rm --user 0 -v "${PWD}/models:/srv/models" callguard-api:local python -m app.provision small
```

`tiny` подходит только для начальной проверки. Для качества, подходящего реальным звонкам, сравните `small` или `medium` на размеченной выборке и измерьте время обработки. После замены файлов модели перезапустите worker: `docker compose restart worker`.

Ollama опциональна. По умолчанию оценка выполняется правилами. Для LLM заранее подготовьте том `callguard-v4_ollamadata` вне рабочего контура, затем задайте ENABLE_LLM=1 и запустите `docker compose --profile llm up -d`. Не подключайте рабочие контейнеры с записями к интернету.

## Структура

- `backend/app/main.py` — создание FastAPI и подключение маршрутов.
- `backend/app/api/` — маршруты авторизации, звонков, отчётов и проверки готовности.
- `backend/app/models.py`, `schemas.py`, `db.py` — таблицы, схемы API и подключение к PostgreSQL.
- `backend/app/security.py`, `audit.py`, `queue.py`, `config.py` — общие зависимости приложения.
- `backend/app/worker.py`, `assessment.py`, `retention.py` — фоновые задания, локальная оценка и удаление по сроку хранения.
- `backend/migrations/`, `backend/tests/` — миграции и тесты.
- `frontend/src/` — интерфейс React; `docker-compose.yml` — локальный запуск.

## Доступ и данные

- Роли: `viewer` просматривает звонки и дашборд; `analyst` загружает записи, повторно запускает неудачные задания, проверяет оценку и выгружает отчёты; `admin` дополнительно видит журнал действий.
- Пароли хранятся как Argon2-хеши. Сессии в Redis действуют 8 часов. Токен интерфейс хранит только в памяти вкладки.
- Создать пользователя: `docker compose exec api python -m app.create_user NAME --role analyst`.
- Сбросить пароль: `docker compose exec api python -m app.create_user NAME --reset-password`.
- Отключить пользователя: `docker compose exec api python -m app.create_user NAME --disable`.
- Аудио, расшифровки и цитаты завершённых звонков старше `RETENTION_DAYS` удаляются; числовые KPI сохраняются каждые пять минут; по умолчанию 30 дней. События загрузки, просмотра звонка, экспорта, входа и проверки оценки пишутся в `audit_events`.
- PostgreSQL и Redis не публикуют порты на Windows. API и интерфейс доступны только через frontend на `127.0.0.1:5173`.

## API и тесты

Документация API отключена по умолчанию; включается через APP_ENV=development при отдельном запуске. Основные маршруты: `POST /api/login`, `POST /api/calls`, `GET /api/calls/{id}`, `POST /api/calls/{id}/retry`, `POST /api/calls/{id}/assess`, `POST /api/calls/{id}/review`, `GET /api/dashboard`, `GET /api/reports/csv`, `GET /api/reports/json`, `GET /api/audit` (только администратор). Дашборд показывает выбранный период (по умолчанию 30 дней). Защищённые маршруты требуют заголовок `Authorization: Bearer <token>`.

`docker run --rm callguard-api:local pytest -q` запускает backend тесты. `docker compose logs -f worker` показывает ошибки обработки. `docker compose stop` останавливает сервисы, сохраняя данные.

## Условия банковского внедрения

Проверенное состояние проекта и решения, которые должен предоставить банк, собраны в [BANK_HANDOFF.md](BANK_HANDOFF.md).

Текущая сборка подходит для локального пилота, но не для обработки реальных клиентских записей без решения следующих задач совместно с ИБ и ИТ банка:

- Подключить согласованный банком провайдер входа сотрудников (OIDC/LDAP/AD), TLS на внутреннем адресе, управление секретами и шифрование диска/резервных копий. Сертификаты НУЦ сайта банка не определяют способ входа сотрудников в CallGuard.
- Согласовать схему ролей, журнал аудита с выгрузкой в SIEM, хранение и удаление резервных копий, восстановление после аварии и ограничения доступа администраторов.
- Проверить качество расшифровки и оценок на размеченной выборке банка; выполнить разделение говорящих, если нужен показатель среднего времени ответа. В моно показатель является оценочной паузой; для стерео требуется явно указать канал оператора.
- Измерить обработку 10-минутных звонков на целевом сервере, провести нагрузочные испытания, анализ зависимостей и проверку безопасности.

Все зависимости, образы и модели для автономного контура нужно предварительно доставить во внутренний реестр. Установка моделей из интернета выполняется только при подготовке среды.

## Замер и проверка

- `docker compose exec worker python -m app.benchmark /srv/storage/ИМЯ_ФАЙЛА` — замер реальной записи, имя файла берётся из тома. Для объективного результата используйте 600-секундный тестовый файл. Замер включает загрузку модели и STT, но не весь путь API → очередь → оценка.
- `WHISPER_THREADS=4`, `WHISPER_BEAM_SIZE=1` — изменяемые стартовые настройки; замерьте также beam=2.
- `OPERATOR_CHANNEL=left` или `right` — только если источник гарантирует раздельные каналы; иначе оставьте пустым.
- Правила проверяют три речевых маркера и стоп-слова. Баллы эвристические; полнота и решение проблемы не подтверждаются автоматически. В моно роли неизвестны. Процент — доля сработавших стоп-критериев из четырёх, не доказанная доля нарушений.
- Существующие установки: новый том storage не содержит старых записей; перед переключением сделайте резервную копию и перенесите содержимое backend/storage в том с правами UID 10001.
- Проверка сети: `docker network inspect callguard-v4_default` (Internal=true); проверьте отсутствие внешнего маршрута из worker. Frontend дополнительно подключён к ingress для публикации порта. Это не аудит безопасности.

## Обновление v3: тональность, роли и период (историческая справка)

Для v4 используйте инструкцию чистой установки в следующем разделе. Новых миграций и моделей не нужно.

- Тональность определяется локально по русским текстовым маркерам, без Ollama. Нейтральная означает отсутствие распознанных эмоциональных маркеров, а не доказательство нейтральной интонации. Не определена — нет текста. При равенстве положительных и отрицательных маркеров выбирается отрицательная; цитаты доступны в карточке.
- Роли: при настроенном OPERATOR_CHANNEL приоритет у каналов; иначе используется представление сотрудника банка и характерные фразы. Неоднозначные сегменты остаются неизвестными. Это не акустическая диаризация: реплики могут содержать несколько голосов. Время ответа по текстовым ролям оценочное.
- Период применяется к дашборду, списку и отчётам по дате загрузки (UTC). День — текущие сутки, неделя/месяц/год — последние 7/30/365 календарных дней включая текущий, произвольные даты включительны. Длинные графики группируются по интервалам. Экспорт оценок по-прежнему включает только подтверждённые значения.
- Старую запись можно открыть и нажать «Пересчитать тональность и роли», если текст сохранился. Повторная расшифровка не нужна. Предыдущее подтверждение сбрасывается; новую оценку необходимо подтвердить. После удаления текста по сроку хранения пересчёт невозможен.

## Версия 4: чистая установка и почасовой график

Новый Compose-проект `callguard-v4` создаёт отдельные тома PostgreSQL, Redis и аудио. Архив не содержит базы, пользователей, сессий, загруженных звонков или `.env`. Старый проект не удаляется. Перед запуском остановите его командой `docker compose -p callguard stop`. Не задавайте старое имя проекта через `-p` или `COMPOSE_PROJECT_NAME`. Если `callguard-v4` уже запускался, его данные сохраняются при повторном запуске. Для новой установки выполните шаги быстрого запуска, включая создание администратора. Можно скопировать только готовую папку `models/` из старого проекта.

За день и при выборе одной даты график содержит 24 часовых интервала 00:00–23:00 UTC, включая нулевые значения. Длинные периоды сохраняют группировку по датам; пустые оценки отображаются прочерком.

Для намеренного удаления старых данных (необратимо) сначала сделайте резервную копию, затем в папке старой версии выполните `docker compose -p callguard down -v`. Это удалит также том Ollama. Для обычной установки v4 эта команда не нужна.
